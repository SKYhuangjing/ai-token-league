## 2. Scope

### 2.1 Admin basicAuth

**Problem**: Admin page (`/admin.html`) and all `/api/admin/*` routes are currently open with zero authentication. Anyone who knows the URL can view usage data, delete participants, and modify pricing.

**Goal**: Protect admin surface with HTTP Basic Auth so that only operators with credentials can access it.

**Boundary**:

- Protects: `/admin.html` (static), all `/api/admin/*` API routes
- Does NOT affect: public leaderboard, participant detail, health, release endpoints
- Credentials: configured via `ADMIN_USERNAME` + `ADMIN_PASSWORD` environment variables
- No credentials configured = admin routes remain open (backward compatible for local dev)
- No user management, no session, no cookies — stateless per-request Basic Auth

**Privacy / Storage / API impact**:

- Privacy: no new data collected or transmitted; auth is server-side header check only
- Storage: no new DB tables or files; credentials live in env vars only
- API: no new or changed endpoints; existing admin routes return 401 when auth is required and missing/invalid

**Status**: experimental — admitted into 0.5 for operator access control on self-hosted instances.

### 2.2 MIN_CLIENT_ENFORCE — 最低客户端版本强制升级

**Problem**: `compatibilityResult()` 对 `clientAppVersion` 的 semver 比较只返回信息性的 `upgrade_available`，不阻断请求。当发布 breaking change 时，无法强制低版本客户端升级。

**Goal**: 通过一个开关 `MIN_CLIENT_ENFORCE`，复用已有的 `LATEST_CLIENT_VERSION`，让服务端可以拒绝低于 latest 版本的客户端（HTTP 426）。

**Boundary**:

- 复用 `LATEST_CLIENT_VERSION` 环境变量作为最低版本门槛（不设置时回退到 `SERVER_VERSION`）
- 新增 `MIN_CLIENT_ENFORCE` 环境变量（默认 `false`）
- `MIN_CLIENT_ENFORCE=true` 时，`clientAppVersion < latestClientVersion` → `compatible: false`，返回 HTTP 426
- `MIN_CLIENT_ENFORCE=false` 时，行为与当前完全一致（`upgrade_available`，不阻断）
- 不引入新的版本常量或策略字段

**Privacy / Storage / API impact**:

- Privacy: 无新数据采集
- Storage: 无新表或文件
- API: `/api/health` 响应增加 `minClientEnforce` 字段；无新端点

**Status**: DONE — `MIN_CLIENT_ENFORCE=true` 时低于 latest 的客户端被 426 拒绝；默认关闭，向后兼容。

### 2.3 Admin 设备面板 — 用户客户端版本可见性

**Problem**: Admin 面板无法看到每个用户的设备正在使用哪个客户端版本。排查兼容性问题时需要手动查 db。

**Goal**: Admin 面板新增 "Devices" tab，展示所有设备的客户端版本、平台、构建信息和最后在线时间。

**Boundary**:

- 只读视图，不修改任何数据
- 新增 `GET /api/admin/devices` 端点，basicAuth 保护
- 新增 admin 面板第 4 个 tab
- 复用 `store.js` 已有的 device + participant 数据，无新存储

**Privacy / Storage / API impact**:

- Privacy: 不对外暴露，仅 admin 可见
- Storage: 无新表；join 已有 devices 和 participants 数据
- API: 新增 `GET /api/admin/devices`（受 basicAuth 保护）

**Status**: DONE — Admin 面板第 4 个 tab 展示所有设备的客户端版本、平台、构建和最后在线时间。

### 2.4 多语言（i18n）

**Problem**: UI 全部硬编码中文或英文，用户无法切换语言。Admin 面板在 3dd5bbd 之后仍为硬编码字符串，与 public web / desktop 的 i18n 覆盖不一致。

**Goal**: 所有用户可见 UI 支持 `zh-CN`（默认）和 `en` 中英文切换；后续新功能必须完成多语言适配。

**Boundary**:

- 核心模块：`src/shared/i18n.js`，提供 `t()` / `updatePageTranslations()` / `createLangSwitcher()`
- 覆盖范围：public web (`index.html` + `app.js`)、desktop (`index.html` + `renderer.js`)、admin (`admin.html` + `admin.js`)
- 不覆盖：CLI（`src/collector/cli.js`，英文即可）、后端 API 响应
- 语言偏好存 `localStorage`（key: `ai-token-league.language`）
- 切换语言时页面 reload 生效

**Privacy / Storage / API impact**:

- Privacy: 无新数据采集；语言偏好仅存本地 localStorage
- Storage: 无新表或文件
- API: 无新或变更端点

**Status**: DONE — public web 和 desktop 已实现中英文切换；admin 面板 i18n 适配完成。

### 2.5 Admin Usage 行级详情语义优化

**Problem**: Admin Usage 表按时间聚合展示用户使用量，但点击昵称时只传 `participantId`，详情抽屉按当前全局筛选范围重新查询该用户数据。用户在 `2026-04-28 / lxc` 行点击昵称时，抽屉可能优先展示该用户 `2026-05-07` 的最新详情，导致列表上下文和详情上下文不一致。

**Goal**: Admin Usage 中点击某一行用户昵称时，默认打开“该用户 + 当前时间桶”的详情，而不是“该用户 + 当前全局筛选范围”的详情。

**Boundary**:

- day grain: 点击昵称打开该用户当天详情
- week grain: 点击昵称打开该用户当前周桶详情
- month grain: 点击昵称打开该用户当前月桶详情
- 详情请求使用当前行的 `periodStart` / `periodEnd` 作为 custom range
- 行内展开按钮只负责展开当前聚合行 composition / top workdirs / models，不打开抽屉
- 如后续仍需要“该用户在当前全局筛选范围内”的详情入口，必须使用明确文案，不复用昵称点击默认行为

**Privacy / Storage / API impact**:

- Privacy: 无新数据采集；仍只展示已有 admin 可见聚合数据
- Storage: 无新表或文件
- API: 优先复用现有 `/api/participants/:id?range=custom&start=...&end=...`；不新增端点

**Status**: DONE — Admin Usage 昵称点击已绑定当前行时间桶；行内展开入口只展开当前聚合行。

### 2.6 Desktop 设置页信息架构重构

**Problem**: Desktop 设置页原先按实现域拆成 Account / Sources / Cloud / Sync / App，`App` tab 同时承载语言、显示偏好、版本、更新、诊断和重置，`Sync` tab 又把本地扫描周期和云端上传状态混在一起，用户难以判断“本地来源扫描”和“云端同步”的真实边界。

**Goal**: 将设置页按用户任务重新分组，让本地来源扫描、云端连接/手动同步、应用偏好、版本运维各自归位。

**Boundary**:

- Tab 顺序调整为：Profile / App / Sources / Cloud / About
- App 只承载应用语言、显示预估成本、显示原始令牌数、登录时启动
- Sources 承载本地来源、Cursor token、workdir aliases、来源扫描周期
- 来源扫描周期定义为本地数据源扫描频率；未配置云端时只扫描本地，配置云端后扫描完成会上传每日汇总
- Sources 通过 tooltip 告知“配置云端后会触发上传”，不把扫描周期放进 Cloud
- Cloud 承载 API base URL、云端状态、手动同步入口、同步状态
- About 承载版本状态、更新策略、诊断导出、重置本地数据
- 不新增配置字段；复用 `autoRefreshEnabled` 和 `refreshIntervalMinutes`

**Privacy / Storage / API impact**:

- Privacy: 无新数据采集；仅重排现有设置入口和说明文案
- Storage: 无新表或文件；配置语义保持兼容
- API: 无新或变更端点

**Status**: DONE — Desktop 设置页已按 Profile / App / Sources / Cloud / About 重构；来源扫描周期已回到 Sources，并通过 tooltip 说明云端配置后的同步行为。

### 2.7 Model Price 交互优化

**Problem**: Admin 模型价格页能看到缺失价格和自定义价格，但缓存读取价格不够显性；处理 Missing Price 时，管理员需要手动复制模型名到价格表单，容易输错。

**Goal**: 让 Admin pricing 面板能直接展示缓存读取价格，并让 Missing Price 任务点击后联动填充模型价格输入框。

**Boundary**:

- Pricing form 包含 input / output / cache read / cache write 四个价格输入
- Custom prices 和 OpenRouter cache 列表展示 input、output、cache read 价格
- Missing Price task 点击卡片后，将缺失模型名填入 `#price-model` 并 focus 到输入价格区域
- 保留已有 model price alias 能力；缺失价格可以继续映射到已有价格模型
- 不改变上传用量模型名、不改变排行口径

**Privacy / Storage / API impact**:

- Privacy: 无新数据采集
- Storage: 复用现有模型价格和别名存储
- API: 复用已有 admin pricing / alias API；无新端点

**Status**: DONE — Admin pricing 面板支持缓存读取价格展示，Missing Price 任务可联动填充模型价格表单。

### 2.8 公共下载和语言切换展示优化

**Problem**: Public 页面下载区域占用头部空间较多，语言切换器位置在 public/admin/desktop 多处不够一致，影响首屏信息密度和切换可见性。

**Goal**: 压缩公共页头部占高，保留下载能力，同时把语言切换器放到更稳定、可发现的位置。

**Boundary**:

- Public masthead 压缩高度，给排行榜表格释放首屏空间
- 下载区不再使用展开式文案块；改为平台选择 + 下载按钮
- 删除“下载客户端”标题文案，但保留平台下拉和下载按钮
- Admin 语言切换器移动到 masthead 并右对齐；窄屏回退到左侧布局
- Desktop 语言切换器放到 Settings / App tab，与显示偏好和登录启动同组
- 所有新增或调整文案继续走 `src/shared/i18n.js`

**Privacy / Storage / API impact**:

- Privacy: 无新数据采集
- Storage: 语言偏好仍仅存 localStorage
- API: 下载 manifest 仍来自既有 release API；无新端点

**Status**: DONE — public 下载区、admin 语言切换器和 desktop App tab 语言入口已完成展示优化。

### 2.9 版本 bump 脚本

**Problem**: 发布版本号散落在 `package.json`、README、AGENTS、CLAUDE 和 roadmap 文档中，手工升级容易遗漏或造成 npm scripts 与 package version 不一致。

**Goal**: 提供 `npm run bump -- <version>` 快速升级版本号，并降低打包脚本里的硬编码版本风险。

**Boundary**:

- 新增 `scripts/bump-version.js`
- 新增 `npm run bump -- <new-version> [--date YYYY-MM-DD]`
- 脚本更新 `package.json`、`README.md`、`README.en.md`、`CLAUDE.md`、`AGENTS.md`、`doc/roadmap.md`
- CHANGELOG 和新版本 baseline/task 文档仍保留人工维护
- 移除 electron-packager npm scripts 中硬编码的 `--app-version`

**Privacy / Storage / API impact**:

- Privacy: 无影响
- Storage: 无运行时存储变更
- API: 无影响

**Status**: DONE — 新增 bump 脚本，package scripts 由 `package.json` version 作为版本真源。

### 2.10 本地服务快速启动脚本

**Problem**: 本地启动后端服务时，需要手动 source env、处理端口占用、选择前台或后台运行；不同环境下容易遗漏参数。

**Goal**: 提供一个可复用脚本快速加载指定 env 并启动本地服务端。

**Boundary**:

- 新增 `scripts/start-server.sh`
- 默认加载 `env.local`，支持 `--env FILE`
- 支持 `--smoke`
- 支持 `--detach`、`--log FILE`、`--pid FILE`
- 检查 Node.js >= 22
- 若目标端口被占用，自动选择随机空闲端口并导出 `PORT`
- 不替代生产部署脚本；定位为本地开发和验证入口

**Privacy / Storage / API impact**:

- Privacy: 无新数据采集
- Storage: detached 模式可写入指定 log / pid 文件
- API: 无新或变更端点

**Status**: DONE — 新增本地服务快速启动脚本，支持 env 选择、smoke、detach、log 和 pid 参数。

### Admin basicAuth

Manual verification:

1. Start server with `ADMIN_USERNAME=admin ADMIN_PASSWORD=secret npm start`
2. `curl -I http://127.0.0.1:8787/admin.html` → expect 401
3. `curl -u admin:secret -I http://127.0.0.1:8787/admin.html` → expect 200
4. `curl http://127.0.0.1:8787/api/admin/usage` → expect 401
5. `curl -u admin:secret http://127.0.0.1:8787/api/admin/usage` → expect 200
6. `curl http://127.0.0.1:8787/api/public-leaderboard` → expect 200 (public, no auth)
7. Start server without `ADMIN_*` env vars → all routes remain open (backward compatible)
