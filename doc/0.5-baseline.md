## 2. Scope

### 2.1 Admin basicAuth

**Problem**: Admin page (`/admin.html`) and all `/api/admin/*` routes are currently open with zero authentication. Anyone who knows the URL can view usage data, delete participants, and modify pricing.

**Goal**: Protect admin surface with HTTP Basic Auth so that only operators with credentials can access it.

**Boundary**:

- Protects: `/admin.html` (static), all `/api/admin/*` API routes
- Does NOT affect: public leaderboard, participant detail, health, release endpoints
- Credentials: configured via `ADMIN_USERNAME` + `ADMIN_PASSWORD` environment variables
- No credentials configured = admin routes remain open (backward compatible for local dev)
- No user management, no session, no cookies — stateless per-request Basic Auth

**Privacy / Storage / API impact**:

- Privacy: no new data collected or transmitted; auth is server-side header check only
- Storage: no new DB tables or files; credentials live in env vars only
- API: no new or changed endpoints; existing admin routes return 401 when auth is required and missing/invalid

**Status**: experimental — admitted into 0.5 for operator access control on self-hosted instances.

### 2.2 MIN_CLIENT_ENFORCE — 最低客户端版本强制升级

**Problem**: `compatibilityResult()` 对 `clientAppVersion` 的 semver 比较只返回信息性的 `upgrade_available`，不阻断请求。当发布 breaking change 时，无法强制低版本客户端升级。

**Goal**: 通过一个开关 `MIN_CLIENT_ENFORCE`，复用已有的 `LATEST_CLIENT_VERSION`，让服务端可以拒绝低于 latest 版本的客户端（HTTP 426）。

**Boundary**:

- 复用 `LATEST_CLIENT_VERSION` 环境变量作为最低版本门槛（不设置时回退到 `SERVER_VERSION`）
- 新增 `MIN_CLIENT_ENFORCE` 环境变量（默认 `false`）
- `MIN_CLIENT_ENFORCE=true` 时，`clientAppVersion < latestClientVersion` → `compatible: false`，返回 HTTP 426
- `MIN_CLIENT_ENFORCE=false` 时，行为与当前完全一致（`upgrade_available`，不阻断）
- 不引入新的版本常量或策略字段

**Privacy / Storage / API impact**:

- Privacy: 无新数据采集
- Storage: 无新表或文件
- API: `/api/health` 响应增加 `minClientEnforce` 字段；无新端点

**Status**: DONE — `MIN_CLIENT_ENFORCE=true` 时低于 latest 的客户端被 426 拒绝；默认关闭，向后兼容。

### 2.3 Admin 设备面板 — 用户客户端版本可见性

**Problem**: Admin 面板无法看到每个用户的设备正在使用哪个客户端版本。排查兼容性问题时需要手动查 db。

**Goal**: Admin 面板新增 "Devices" tab，展示所有设备的客户端版本、平台、构建信息和最后在线时间。

**Boundary**:

- 只读视图，不修改任何数据
- 新增 `GET /api/admin/devices` 端点，basicAuth 保护
- 新增 admin 面板第 4 个 tab
- 复用 `store.js` 已有的 device + participant 数据，无新存储

**Privacy / Storage / API impact**:

- Privacy: 不对外暴露，仅 admin 可见
- Storage: 无新表；join 已有 devices 和 participants 数据
- API: 新增 `GET /api/admin/devices`（受 basicAuth 保护）

**Status**: DONE — Admin 面板第 4 个 tab 展示所有设备的客户端版本、平台、构建和最后在线时间。

## 4. Verification

### Admin basicAuth

Manual verification:

1. Start server with `ADMIN_USERNAME=admin ADMIN_PASSWORD=secret npm start`
2. `curl -I http://127.0.0.1:8787/admin.html` → expect 401
3. `curl -u admin:secret -I http://127.0.0.1:8787/admin.html` → expect 200
4. `curl http://127.0.0.1:8787/api/admin/usage` → expect 401
5. `curl -u admin:secret http://127.0.0.1:8787/api/admin/usage` → expect 200
6. `curl http://127.0.0.1:8787/api/public-leaderboard` → expect 200 (public, no auth)
7. Start server without `ADMIN_*` env vars → all routes remain open (backward compatible)

### MIN_CLIENT_ENFORCE

1. Start server without `MIN_CLIENT_ENFORCE` → low-version client gets `upgrade_available`，不阻断
2. `MIN_CLIENT_ENFORCE=true npm start`，health 响应含 `minClientEnforce: true`
3. `MIN_CLIENT_ENFORCE=true npm start`，低版本 client 注册 → 426
4. `MIN_CLIENT_ENFORCE=true npm start`，latest 版本 client 注册 → 200

### Admin 设备面板

1. `curl -u admin:secret http://127.0.0.1:8787/api/admin/devices` → JSON 设备列表
2. `curl http://127.0.0.1:8787/api/admin/devices` → 401（需认证）
3. admin.html 点击 Devices tab → 设备表格展示 nickname、版本、平台、build、last seen
