# AI Token League 0.4 开发任务

## 0. 范围

0.4 聚焦首次启动体验、客户端排障能力和早期服务端数据修正：将静默初始化改为知情同意的引导流程，提供本地诊断导出用于对账云端数据与本地数据，并允许管理员按用户重置已上传聚合数据。

来自 `roadmap.md` 的计划功能：

- 初始化引导：首次启动引导用户设置昵称、选择数据源、配置 Cloud Connection，并明确隐私边界。

成功标准：

- 新用户在首次启动时理解产品用途、隐私模型和数据源选择。
- Desktop 用户通过 5 步向导完成配置；跳过向导使用安全默认值。
- CLI 用户通过交互式 `init` 命令完成配置。
- 隐私声明覆盖所有 `FORBIDDEN_UPLOAD_FIELDS`。
- Desktop 用户可以在 App tab 导出本地诊断包，用于排查 scan/sync/upload queue/cloud data 不一致。
- Admin 用户可以在数据统计存在问题时重置单个 participant 的服务端聚合数据，并让该客户端重新 register/sync 最新数据。
- Admin 用户可以将 Missing Price 中的展示模型显式映射到已有计费模型，修复 Cursor `Premium (...)` 等 display model 的成本估算，同时不改展示模型。
- Desktop 用户可以开启后台静默更新：后台检查、下载并校验 zip artifact，在安全空闲窗口自动安装并重启，避免用户手动打开 Finder/File Explorer 替换安装目录。

## 2. 产品需求

### R1 Desktop 初始化向导

问题：

- 当前首次启动只显示一个内联 onboarding card，只有昵称输入和 3 个按钮。
- 身份密钥对在后台静默生成，用户无感知。
- 没有解释产品用途、隐私模型或数据源。
- 用户必须手动导航到 Settings 才能配置源和 Cloud。

成功标准：

- 首次启动显示 5 步向导替代 onboarding card。
- 向导展示产品用途、隐私声明、身份信息、源检测和 Cloud 配置。
- 用户可以完成向导或跳过；跳过使用安全默认值。
- 完成或跳过后 `desktopAutoInitialized` 置为 `false`。

### R2 隐私披露

问题：

- `FORBIDDEN_UPLOAD_FIELDS` 定义了 14 个禁止上传字段，但从未向用户展示。
- 用户不知道什么数据被采集、什么数据不被采集。

成功标准：

- 向导 Welcome 步骤展示人类可读的隐私声明。
- 隐私声明覆盖 prompts、responses、code、paths、tokens、keys。
- CLI 交互式 init 也展示隐私摘要。

### R3 源自动检测

问题：

- Provider `detect()` 已存在但未在引导中暴露。
- 用户不知道本机安装了哪些 AI 工具。

成功标准：

- 向导 Sources 步骤调用 `providerHealth()` 展示检测结果。
- 检测到的源预启用；用户可以切换。
- 未检测到的源显示 "Not found" 并提供 "Add location"。
- Cursor 默认关闭，即使检测到。

### R4 CLI 交互式初始化

问题：

- CLI 首次使用直接报错："collector is not initialized"。
- 用户必须知道 `--nickname` 标志才能初始化。

成功标准：

- 无 config 且无 `--nickname` 标志时，`init` 进入交互模式。
- 交互模式提示昵称、展示检测结果、提示 API URL。
- 有 `--nickname` 或 `--api` 标志时行为不变。

### R5 客户端可观测性与诊断导出

问题：

- 云端 `usage_daily` 和用户本地检测结果不一致时，缺少统一证据包。
- 目前只能分别查看 UI、usage cache、upload queue、服务端数据，排查链路断裂。
- Windows 小规模试用暴露出跨日去重、多设备重复上传等问题，需要客户端侧 scan/sync 证据辅助定位。

成功标准：

- Desktop 运行态写入本地 `runtime-log.jsonl`，记录 scan、cache、sync、queue、API health、background refresh 等关键事件。
- Settings > App 提供 `Export diagnostics` 按钮。
- 诊断包包含脱敏 config、app/client 信息、background status、usage-cache rows、upload queue aggregate payload、source index 摘要、最近 runtime log。
- 诊断包不包含 identity private key、Cursor token、provider root 真实路径、prompt、response、source code、full transcript。
- 导出的 JSON 能用于和云端 `usage_daily` 按 `participantId/deviceId/day/provider/model/workdirHash/sourceFingerprint/totalTokens` 对账。

### R6 Admin 用户数据重置

问题：

- 前期 parser、provider 规则或客户端统计口径存在问题时，服务端可能已经保存了错误的聚合数据。
- 仅删除 `usage_daily` 不够；旧 `upload_batches` 会让同一个客户端 payload 被判定为 duplicate，无法快速重新接收数据。
- 手工改 JSON/MySQL 表容易漏删设备、workdir、批次或聚合缓存。

成功标准：

- `/admin.html` Usage ranking 每个用户行提供 `Reset user` 操作。
- 操作需要确认，避免误删。
- 后端提供 `DELETE /api/admin/participants/:participantId`。
- 删除范围包含 participant、devices、workdirs、usage_daily、upload_batches，并失效 aggregate cache。
- MySQL 路径按外键顺序在事务内删除。
- 删除后，同一个客户端执行正常 `register` + `sync` 可以重新上传数据，不被旧 upload batch dedupe 阻挡。

### R7 Admin 模型计费映射

问题：

- Cursor dashboard 会产生 `Premium (Codex 5.3)` 这类展示模型。
- 展示模型必须保留原样，不能为了计费改成 OpenRouter key。
- 计费层不应硬编码 `Premium (...)` 或 `Codex x.y` 的猜测规则。
- Admin Missing Price 需要快速把缺价模型绑定到已有 custom/OpenRouter 价格。

成功标准：

- Cursor `default`、`auto`、空模型名采集为展示模型 `Auto`。
- Cursor `Premium (...)` 按原字符串进入 usage facts 和 UI。
- Missing Price 行可以选择已有 priced model 并保存 alias。
- alias 保存后重算成本，`model` 保持展示模型，`pricingModel` 记录目标计费模型。
- alias 可删除；删除后对应模型重新进入 Missing Price。

### R8 Desktop 后台静默更新

问题：

- 当前后台能力只会定时检查更新，不会下载、校验、安装或重启。
- 手动 `Download and restart` 已能避免用户替换安装目录，但仍要求用户主动点击。
- 如果未来服务端收紧客户端兼容窗口，旧客户端需要一个不依赖用户手工操作的升级路径。

成功标准：

- Settings > App 增加静默更新模式：`notify`、`auto_download`、`auto_apply_on_idle`。
- 默认模式为 `notify`：只后台检查并提示，不静默下载或重启。
- `auto_download` 模式后台读取 app-server release config、下载当前平台 zip artifact、校验 checksum，并记录 ready 状态。
- `auto_apply_on_idle` 模式在 verified package ready 后自动安装并重启，但必须等待安全空闲窗口。
- 安全空闲窗口要求：没有 foreground scan、background refresh/sync、diagnostics export、config import/export、identity import/export、update download/apply 正在运行。
- mandatory update 可在 `notify` 模式下升级为 `auto_apply_on_idle`，但仍受安全空闲窗口约束。
- local-only 或 Cloud 不可达时不做静默更新，因为 app-server release config 是唯一更新源。
- 失败时当前 app 保持可用，Settings > App 展示失败状态，runtime log 记录 check/download/checksum/apply 的失败原因。

## 7. 已确认决策

| 决策 | 结论 | 约束 |
| --- | --- | --- |
| 身份创建 | 自动创建，向导中展示 | 不增加摩擦，用户看到但不手动生成 |
| 向导可跳过 | 是，右上角 "Skip setup" 链接 | 使用默认值：nickname "anonymous"、检测到的 provider 全开、无 API |
| Cloud 可选 | 是，"Skip cloud" 按钮 | 本地模式可查看 usage，无 update check |
| 向导替换 onboarding-card | 是，card HTML 移除 | 避免两个首次运行 UI 并存 |
| CLI 交互模式 | 仅无 config 且无标志时 | 保留现有脚本用法 |
| Cursor 默认关闭 | 即使检测到也默认关闭 | 需要单独 token，预启用会误导用户 |
| 诊断导出入口 | 放在 App tab | 诊断包覆盖客户端运行态，不只是 Sync 配置 |
| 诊断包格式 | 本地 JSON 文件 | 便于用户主动导出并用于云端/本地数据对账 |
| Admin reset 范围 | 单个 participant 的服务端聚合数据 | 修复前期错误统计，不触碰用户本地身份和缓存 |
| 删除 upload batch | 是，随 usage 一起删 | 避免重新 sync 被旧批次 hash 判重拦截 |
| 向导全屏模态 | 是，`modal-backdrop` 全屏遮罩 | 用户必须完成或跳过向导才能操作主界面；Today 面板在遮罩下方预加载 |
| 配置导出/导入 | 完整配置（非仅 identity） | 包含 apiBaseUrl、provider、aliases 等；旧 profile 文件（仅 identity 四字段）兼容导入，缺失字段使用默认值 |
| Cursor Auto 展示 | `Auto` | 与 `Premium` 首字母大写展示风格一致，不改变计费规则 |
| Premium 计费 | 只走显式 alias | 避免基于展示名猜测计费模型，Missing Price 中人工确认目标 priced model |
| 重启升级 | 下载校验后自动安装并重启 | macOS zip 替换运行中的 `.app`；Windows zip 替换运行中的 exe 目录；旧包首次升级到含该能力的新包仍需先安装一次 |
| 静默更新默认策略 | 默认 notify，用户可切到 auto_download 或 auto_apply_on_idle | 后台静默准备更新可以降低旧客户端滞留；默认不突然重启，避免打断 scan/sync/诊断导出 |
| 静默更新数据源 | 只使用 app-server release config | 不新增客户端内置 manifest URL 或本机 env fallback |
| 静默 apply 边界 | 只支持 zip artifact | 非 zip installer 语义不同，继续作为 verified download handoff |
