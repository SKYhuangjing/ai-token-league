# 算力共享插件改造设计与研发交接

日期：2026-09-20。状态：**设计交接稿；研发任务待分派，未开始实现或运行验收**。

评审基线：`develop @ 6199b95`，包含本地未提交的 compute-sharing `0.9.5` 改动；CPA crate 当前版本 `0.4.0`。这是源码快照，不代表线上后端、OSS 插件包或用户安装版本已经一致。

## 1. 产品结论与交付目标

当前架构适合熟悉 CLIProxyAPI（下文简称 CPA）的用户共享模型访问能力。主要缺口是用户不能稳定回答三个问题：我是否仍在分享、我到底能用多少、不能用时怎样恢复。

本轮保留 CPA 执行引擎、后端控制面、桌面插件的职责划分，围绕完整用户流程修复产品语义。共享的是经 CPA 提供的模型 API 访问能力，不是把一台电脑的 GPU 分配给他人。

目标：

| 用户 | 交付标准 |
| --- | --- |
| 分享者 | 能区分面板开关与服务开关；能看懂实际配置、当前借用者和停止后果；遇到故障仍保留管理入口 |
| 借用者 | 能选择可用资源和具体模型，拿到适合目标工具的配置，完成一次真实协议请求；能看懂自己的额度与失效原因 |
| 管理员／研发 | 控制台、Web、CLI、后端和 CPA 对状态及计量使用同一口径；发布可分批、可回滚、可追踪 |

成功指标是本轮的验收目标，不是已经测得的结果：

- 在已安装并初始化 ATL、已有可用资源的条件下，新借用者无需研发口头帮助，在 3 分钟内完成目标工具首次请求；配置路径以实际支持的工具为准。
- 5 位未参与开发的使用者全部能正确区分“关闭面板”“暂停资源”“停止分享”。没有试用样本时，记录“未测”，不能用自动化测试代替理解度验收。
- 每个故障场景同时给出原因、数据新鲜度及一个可执行的下一步，不把失败呈现为空白或正常状态。

## 2. 当前链路与证据

```text
借用工具 ── 临时 Key、模型请求 ──> 分享者 CPA / atl-share ──> 模型供应商
                                      │ 心跳、计量、策略同步
                                      ▼
桌面插件 ── Rust 特权命令／查询 ──> ATL 后端控制面
  │                                     │
  └─ 本机认领存储 sharing-borrow.json    └─ JSON 或 MySQL 控制面存储
```

平台只接收共享管理和计量元数据。请求内容经过分享者 CPA；“ATL 后端不接收内容”和“分享者无法看到内容”是不同承诺。

| 问题 | 代码确认的现状 | 源码入口 |
| --- | --- | --- |

**计量补充核对**：不能把当前单 Key 限额简单定义为“日上限”。CPA 的 `settled_by_key` 按 `windowDay` 重置，但后端心跳又从各车道当前窗口的 `ledger.byKey` 恢复它；本地单 Key 增量和车道高峰倍率的口径也不同。入口为 [heartbeatResponse](../src/backend/sharing-cpa.js)、[restore_settled / gate_request](../cpa-plugin/src/core_state.rs)、[handle_usage](../cpa-plugin/src/lib.rs)。这是需要统一并验证的执行契约，不应只给当前字段加一个“每日”标签。

本报告的现状结论来自静态代码检查。真实网络、上游模型发现、两种推理协议、跨平台安装和线上版本一致性均未在本轮验证。

## 3. 范围与分批策略

### A 批：现有行为下的体验修复

处理开关名称、首次引导、策略回显、估算文案、信任说明、错误态、筛选及认领后的工具配置。保留现有停止／撤销语义，先把它们说清楚。每个资源仍绑定一把 Key，不引入自动路由。

### B 批：管理与计量契约升级

增加保留 Key 的临时暂停、owner 单 Key 撤销、按车道窗口统一单 Key 计量和策略生效确认。该批涉及 API、执行语义及可能的存储字段，必须按 §10 的版本门控交付，不能仅发布远端 JS 卡片。

### 本期不包含

- 自动安装／重启／修改用户 CPA、开放监听地址或穿透网络；不接管用户现有上游凭证。
- 供应商真实额度预测、自动保护自用额度、跨节点负载均衡、价格结算、信用评分、预约排队。
- 自动修改第三方工具的持久配置；先生成可复制、可撤回的配置说明。
- 重做插件平台、建立通用工作流引擎，或将共享业务重新塞回平台命令枚举。
- 恢复已失效 Key 的完整历史列表；保留当前“失效项退出活动列表”的方向。

## 4. 页面与目标流程

### 4.1 首次进入与信息层级

- 默认突出“借用资源”；已有 owner 可以保持上次选择的“我的分享”。
- 未注册分享者保留一行“我要分享”，打开准备指引。纯借用者不必看到整个 owner 控制台。
- 面向用户称为“共享资源”；需要对应 CLI/API 时在说明中标注 `lane`。内部数据字段和 ID 不因改名而迁移。
- “我的借用”优先显示正在使用的资源；地址和 Key 放在可展开的接入配置中，避免每次管理都先阅读四行凭证。
- owner 编辑器基础项为名称、模型、预算、周期、名额；开放时段和高峰倍率放入高级设置。已配置的高级规则必须在收起摘要中可见。

### 4.2 分享者准备流程

```text
我要分享 → 检查 ATL 身份／CPA／执行插件／控制面地址
         → 缺项给出安装或配置指引 → 重新检测
         → 节点已注册 → 配置共享资源 → 查看规则摘要与当前服务状态
```

检测须区分未安装、未初始化、路径未发现、网络失败、版本不支持；不能统一为“未注册”。本机检测不读取或回显上游凭证。安装步骤沿用现有 CPA 机制；现有脚本只覆盖本机 dylib 路径，不能在没有真实平台验证时宣称 Windows／Linux 一键安装。

CPA 当前配置可能触发自动注册，准备页应如实显示已经发生的注册，不能把向导最后一步伪装成唯一的上线开关。本期不改变 CPA 的自注册方式。

配置摘要例：模型范围、共享预算及重置时间、每个 Key 的上限、开放时段和时区、高峰折算、可同时持有的 Key 数、当前借用者数。保存后显示服务端归一化结果，不能只显示输入值。

### 4.3 借用流程

```text
选择模型范围／资源 → 查看分享者、使用规则与内容流向
                  → 认领 → 选择目标工具和具体模型
                  → 生成对应配置 → 按目标协议测试 → 在工具中实际使用
```

- 目录支持按模型范围过滤；具体模型从经过验证的 CPA 模型目录中选择，并取 lane 白名单交集。通配符只用于范围，不得当作可发送的 model ID。
- 模型发现优先使用借用 Key 经受限 sidecar 请求同一已认领端点的模型目录。先验证该 CPA 版本是否允许这一路由；不允许时显示“模型目录不可用”，提供带说明的手动输入，不能填入猜测模型。
- 首批目标工具为 Claude Code、Codex CLI，以及通用 OpenAI／Anthropic API。研发实施时必须核对本机工具版本、帮助和官方配置契约；不能假设四个环境变量覆盖所有工具。
- 按目标工具生成必要配置，按 shell 区分 Bash/Zsh 与 PowerShell；说明临时会话生效范围、启动步骤及恢复原配置的方法。不得把新 Key 无提示覆盖进用户配置文件。
- 测试使用所选协议和具体模型：OpenAI Chat Completions、Responses 或 Anthropic Messages 各自验证。某一种协议成功不代表其他协议成功。
- 测试按钮明确“发送一次少量 token 的测试请求”；展示结果时间、模型、协议和可操作错误。测试通过仅表示该次探测成功。
- 同一资源已有本机有效 Key 时显示“查看配置”，不再鼓励重复认领。请求期间禁用该认领按钮，防止双击占多个名额；跨进程写入通过 Rust 流程统一完成。
- 首次请求可能早于下一次 CPA 心跳：认领后先显示“等待节点同步”，按受控重试处理首次未识别 Key，不让用户立刻重复认领。持续失败必须展示具体原因。

## 5. 控制动作与状态

### 5.1 面板与服务分别表达

最小实现选择：保留 CPA 独立运行；面板开关改为“显示管理面板／关闭管理面板”，不隐式停止服务。

- 使用一项通用、声明式插件元数据表示“服务运行于外部进程”，宿主据此呈现开关说明与卸载文案；字段定义需同步到插件平台文档和类型。
- 禁用后的插件条目也显示“关闭此面板不会停止外部共享服务”。未加载远端 JS 时，仍能通过已安装元数据呈现这条说明。
- 卸载提供“返回管理”和“仅卸载面板”；说明 CPA 服务和已发 Key 的状态不会因此改变。共享状态无法确认时必须写“未知”，不能写“已停止”。
- “停止分享”放在 owner 状态摘要旁，不能藏在高级策略输入区。
- A 批不增加“停止并卸载”的复合事务；用户先在面板确认停止，再卸载。避免网络停止失败却已经卸掉控制入口。
- 宿主不按 `compute-sharing` ID 写业务特例，不为其他普通查询插件强加共享专用流程。

### 5.2 服务动作矩阵

| 操作 | A 批行为 | B 批目标 | Key／计量影响 |
| --- | --- | --- | --- |
| 关闭面板／退出 ATL | CPA 独立运行 | 保持 | 不撤销、不清账 |
| 暂停单个资源 | 原有破坏性动作明确改名“停用并撤销借用” | 新增临时暂停 `paused` | 暂停期间拒绝请求和新认领；Key 保留、TTL 继续计时、账本不清零 |
| 恢复临时暂停 | 尚无此动作 | `paused → active` | 未过期且未撤销 Key 恢复可用；过期 Key 不复活 |
| 撤销一个借用 | owner 无此能力 | 仅撤销本 share 下指定 Key | 不影响其他人；重试幂等；保留后台审计 |
| 停用并撤销资源借用 | 现有 `suspended` 语义 | 保持明确的终止动作 | 级联撤销；重新开放后需重新认领 |
| 停止全部分享 | 现有 `stopped` 语义 | 保持 | 下线并撤销全部 Key；重新开启不复活旧 Key |
| 管理员下架 | 现有 `suspended` share 语义 | 保持 | owner 不得绕过管理员状态恢复 |

临时暂停不延长 Key 的 TTL，避免隐式占坑。到期续期仍需用户操作；暂停期间不支持通过续期绕过资源限制。

### 5.3 状态与新鲜度

UI 分开表达四个维度，不用一个绿色圆点代替全部事实：

1. 控制面是否连接、最后成功刷新时间。
2. CPA 心跳是否新鲜、策略是否已经同步。
3. 资源是否开放、是否暂停、是否耗尽。
4. 自己的 Key 是否有效、是否达到本周期上限、最近连接测试结果。

owner 状态失败时保留已有视图和草稿，标记“暂时无法更新”，提供重试；服务变更动作在无法确认状态时不可宣称成功。本地没有身份与后端返回不存在必须分别展示。

我的借用发生撤销、到期或资源移除时，退出活动列表并展示一次不含凭证的原因回执；提供重新选择资源入口。首次打开时就已过期的本地记录，Rust 清理结果需携带脱敏摘要，避免记录在 UI 读取前已被过滤而无法解释。

页面可见时最多每 15 秒执行一轮合并刷新，隐藏后停止轮询；返回页面立即刷新。目录、owner、我的借用并发读取并分别呈现，不让 owner 超时阻塞借用目录。重复挂载必须释放计时器和观察器。返回晚的旧请求不得覆盖新状态或写回旧认领列表。

## 6. 额度与计量口径

### 6.1 A 批：先把现有事实显示完整

- owner-status 返回实际 `policy`，表单以当前值回填；自动分配用显式选项表达，不用 `0` 或 placeholder 暗示。
- 认领与 live 响应展示单 Key 限额、有效期、并发限制、车道窗口及高峰规则；无法可靠确定某项剩余额度时显示“待同步／待版本升级”，不虚构精确数字。
- 累计原始 token 与本周期预算扣减分开显示。供应商真实剩余额度未知时明确“分享者设置的预算，不代表供应商剩余额度”。
- “自留”改为“历史用量参考比例”：例如近 7 天使用 1 亿、参考比例 75%，生成 7500 万的建议预算。迁移旧 `reservePct` 为 `referencePct = 100 - reservePct`，一次迁移后写新字段；不改变已发布资源预算。
- 示例和帮助直接写“仅用于创建草稿，不保证自用额度”；真实供应商配额查询只作独立参考，不换算成未经验证的 token 总量。

### 6.2 B 批：统一窗口与预算扣减

推荐决策 D1：单 Key 限额与所属 lane 共用 `windowKey / startsAt / endsAt`，不再混用 share 日窗。高峰倍率同时作用于 lane 与 Key 的预算扣减，原始 token 总量单独保留。

```text
chargedTokens = rawTokens × 该请求归属时刻的高峰倍率
laneRemaining = max(0, laneBudget - laneChargedInWindow)
keyRemaining  = max(0, keyLimit - keyChargedInWindow)
```

两项分别展示。它们是最近已结算快照，存在在途请求和同步延迟；不承诺预留额度，不承诺严格零超冲。若要显示一个总“可用”数字，应标记为估算且使用同一扣减单位。

- share 级只保留统一默认单 Key 限额；自动模式在每个 lane 内按 `floor(lane.budgetTokens / lane.maxClaims)` 算有效上限。显式限额使用 `min(configuredLimit, laneBudget)`。
- 降低预算或上限不清账；已经超出新上限的 Key 停止新增请求，到窗口重置或合法调高后恢复。
- 续期只延长有效期，不重置使用量；重启 CPA、重开 ATL 也不重置账本。
- 窗口使用既有固定网格与 owner 时区规则；UI 展示完整日期、时间及时区，不能把每周重置仅显示为“00:00”。真实供应商滚动窗不得与本地固定网格混称。
- 执行层本地使用量与后端归并必须共享同一窗口、倍率及单 Key 累计语义。跨窗口／高峰边界不能用心跳到达时间替代请求归属时刻。
- 协议按 `keyId + laneId + windowKey + multiplier` 聚合增量，携带原始量和扣减量；后端校验 lane 归属、窗口及倍率，并保证失败重试不重复结算。CS-06 必须完成序号／去重及存储方案评审后实现；不能只给现有按 Key 合并的 delta 多加一个时间字段。
- 心跳进行中产生的本地未确认增量不得被后端旧快照覆盖。验收需覆盖重试、跨窗、重启、并发结算及延迟响应。

这项会改变数据含义，独立提交、独立发布；A 批不得提前展示尚未落地的统一口径。

## 7. 目录、身份与信任说明

### 7.1 目录计算顺序

`模型过滤 → 在匹配车道上计算可认领状态 → 可用性过滤 → 排序 → 折叠 → 独立计数`。

- 可认领必须同时满足 share 在线且 active、lane active 且开放、余额正数、有名额。
- 节点排序只使用匹配资源的状态、剩余比例；心跳新鲜度使用真实目录字段 `updatedAt`，不读取仅 owner 视图才有的 `share.plugin.lastHeartbeatAt`。
- “因模型过滤隐藏”和“暂不可认领”分别计数；不可用组也遵守当前模型过滤。
- 折叠组显示具体原因和恢复时间，包括已满、暂停、时段未开、额度耗尽；按资源维度表达，不用 share 默认名额代替 lane 实际名额。
- 公开 Web 使用同一 lane 数据口径，避免“网页显示有量，进入 App 却耗尽”。Web 保持只读，并给出下载／打开客户端的明确导航。
- 自动刷新不打断正在编辑的表单，不改变已聚焦控件，不重置用户的过滤和展开状态。

### 7.2 信任说明

认领前常驻简短说明，接入配置中保留可展开详情。建议中文：

> 模型请求会经过分享者的 CPA 服务，分享者可能接触请求和响应内容。ATL 平台接收共享管理与用量元数据。请只使用你信任的分享者。

展示分享者昵称及可公开的身份标识，遵守现有身份可见性规则，不新增公开真实 participantId、邮箱或设备绝对路径。“实名联赛身份”表示可归属，不等于平台担保。

Key 是 bearer 凭证；认领时签名绑定身份不等于请求被硬件锁定。删除“Key 只能在此设备使用”之类未经实现的承诺。Key 遮罩时 tooltip、无障碍名称、toast 和日志均不能泄露完整值。

## 8. 技术边界与拟新增契约

以下是目标契约，**不是当前已存在的接口清单**。研发以现有实现扩展，不再维护另一套借用业务逻辑。

| 面 | 最小改动 | 约束 |
| --- | --- | --- |
| 桌面卡 | 状态、引导、配置生成、筛选；借用动作迁入 Rust flow | 不直接 import 宿主私有模块；所有新命令声明 manifest 权限 |
| 插件宿主 | 声明式外部运行说明、面板开关及卸载文案；必要的卸载清理契约 | 只加通用能力，不增加共享专用命令或业务分支 |
| Rust sharing crate | 复用 `flow::{claim,renew,revoke,live}`；新增受限模型发现、协议测试、owner 动作 | 整个读改写周期加共享存储锁，不能只锁最终覆盖写；CLI 和卡片复用同一实现 |
| owner-status | 返回 `policy`、结构化故障、策略目标版本／节点确认版本 | 本地检测可报告身份是否存在，secret 不进入 webview |

## 10. 发布、迁移与回滚

### 10.1 A 批

1. 先部署向后可读的后端响应补全，再交付含 Rust／宿主能力的客户端，最后发布依赖这些能力的远端插件包。
2. 发布渠道必须验证最低宿主能力；旧宿主继续固定在上一插件包，新安装也不得无检查地拿到不支持的包。当前平台若没有此能力，先补最小能力声明与校验，不用 JS 静默吞错作降级。
3. 本地认领字段补全走读取后规范化；未知限额显示未知，不因字段缺失重新签 Key。旧参考参数做一次迁移，保留回滚可读窗口，稳定后移除迁移分支。
4. 回滚 UI 包不停止 CPA、不撤销 Key、不清空账本。对已新增本地字段进行旧版读写往返验证，避免旧版覆盖写丢失凭证。

### 10.2 B 批

1. 先评审并部署新旧协议可区分的后端及存储迁移；CPA 心跳声明协议版本，UI 能力从服务端获知，不按 UI 包版本猜测。
2. 逐节点升级 CPA 后，才开放该节点的新计量和暂停能力。已有 `suspended` 仍解释为已撤销；禁止批量重映射为保留 Key 的 `paused`。
3. 尽量在现有 lane 窗口边界切换计量协议；窗口中切换时必须从后端当前已结算账本建立明确基线，不清零、不重复计量。现有数据不足以重建的部分标记边界，不能伪造历史。
4. 计量协议降级不得直接把新账本送入旧执行逻辑。故障节点暂停新增借用并停止借用服务，修复或完成受控回迁后再恢复；分享者自用 Key 不受影响。
5. 发布记录分别列出 backend、桌面／sidecar、JS 插件、CPA dylib 四个版本以及迁移状态。每批都记录适配过渡期限，稳定后删除旧路径，避免永久双实现。
