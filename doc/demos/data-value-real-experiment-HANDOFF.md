## 3. 已确认的产品原则

### 3.1 数据优先级

产品表达优先级是：

1. 先看到真实数据规模。
2. 再理解周期变化、贡献集中度、模型结构和来源结构。
3. 再进入真实用户运营与数据质量判断。
4. 客户端下载和使用引导是次要动作，不抢占数据首屏。

### 3.2 四页面职责

| 页面 | 核心问题 | 当前实验表达 |
| --- | --- | --- |
| 首页 | 社区当前发生了什么 | 周期 Token、周期进度、活跃人数、Top 贡献、趋势、来源结构 |
| 排行榜 | 谁贡献了主要用量 | `totalTokens` 排名、贡献占比、Token 组成、主要模型、参与者下钻 |
| 分析 | 当前总量由什么构成 | 时序趋势、缓存占比、来源集中度、模型结构、活跃热力图 |
| Admin | 哪些真实用户产生用量，数据是否可信 | 真实昵称使用量排名、主要模型/来源、来源质量、价格覆盖和设备同步 |

### 3.3 身份与隐私边界

- 公开页面只使用服务端返回的匿名 `displayName` 和 `displayId`。
- Admin 页面使用真实 `nickname`，因为其职责是内部用户运营。
- Admin 设备表只展示设备短标识、昵称、版本、平台和最后同步时间。
- 实验页面没有展示设备 LAN IP。
- 实验脚本只发起 GET 请求，不写入或修改业务数据。
- 预估成本只用于解释，不参与排名；排名真值仍是 `totalTokens`。

## 4. 真实 API 映射

### 4.1 公开页面

| API | 用途 |
| --- | --- |
| `GET /api/board/summary` | 今日、本周、本月、累计 Token 和预估成本 |
| `GET /api/board/leaderboard?period=<period>&limit=100` | 完整周期参与者集合、公开匿名排名、Token 组成和模型 |
| `GET /api/board/analytics?period=<period>` | 时间序列、模型、来源、缓存、成本和热力图 |

公开周期值：

- `today`
- `this_week`
- `this_month`
- `all`

### 4.2 Admin 页面

| API | 用途 |
| --- | --- |
| `GET /api/admin/usage-ranking?range=<range>&page=1&pageSize=10` | 真实用户使用量排名 |
| `GET /api/admin/quality?range=<range>` | 来源质量、价格覆盖、异常日期和多设备用户 |
| `GET /api/admin/devices` | 客户端版本、平台和同步状态 |

Admin 周期值：

- `today`
- `last7`
- `month`
- `all`

## 5. 三轮评审结论

### 第一轮：真实数据口径

发现 `analytics.participantCount=67` 表示全体参与者，不等于当前周期活跃人数。

处理：

- 排行榜请求调整为 `limit=100`。
- 当前周期活跃人数改为完整排行榜 `items.length`。
- 2026-07-18 的实际观察结果从错误的 67 人修正为今日 4 人、本月 42 人。

### 第二轮：进行中周期表达

发现把“本月至今”直接与“上月完整月”写成增长或下降，会把未完成周期误解为完整周期。

处理：

- 不再写“本月下降 7.6%”。
- 改为“本月至今达到上月完整周期的 92.4%”。
- 今日和本周使用相同的“截至当前 / 上一完整周期”口径。
- 今日趋势使用真实逐小时数据，并过滤尚未发生的未来小时。

### 第三轮：加载、交互与隐私

发现公开首页原本会等待 Admin 质量和设备接口，公开数据被无关请求拖慢；Admin 待办中的按钮也没有真实动作。

处理：

- 公开页和 Admin 改为按页面懒加载。
- 刷新按钮只刷新当前页面的数据域。
- Admin 无效操作按钮改为“需关注 / 已覆盖 / 辅助信息”等真实状态。
- 公开端保持匿名，Admin 保留真实排名，但不展示 LAN IP。

## 8. 暂不合入的原因

当前方向具备数据价值，但还不满足正式合入条件：

1. 真实数据分布与静态 Demo 差异明显，需要继续观察多个业务日。
2. 进行中周期与完整周期只能表达“进度”，还缺少服务端同长度对比数据。
3. 今日逐时数据存在同步延迟，低值不一定代表真实使用下降。
4. Demo 为中文实验页，尚未接入正式 `zh-CN` / `en` i18n。
5. Demo 尚无专门的自动化交互测试、空数据测试和 Admin 鉴权失败测试。
6. Admin 设备接口当前是主要加载耗时来源，需要正式实现时继续拆分或缓存。
7. 真实数据实验尚未验证正式首页、排行榜、分析和 Admin 的信息密度承载能力。

## 9. 后续恢复方式

### 9.1 继续预览

从项目根目录启动服务：

```bash
scripts/start-server.sh --env env.local
```

打开：

```text
http://127.0.0.1:8787/data-value-demo.html?experiment=real-data#home
```

推荐依次检查：

1. 首页切换今天、本周、本月和累计。
2. 排行榜点击 Top 3 以外的参与者。
3. 分析页对比今日逐时和本月逐日趋势。
4. Admin 对比今天和本月真实用户排名。
5. 检查价格缺口、来源精确率和超过 24 小时未同步的设备数量。

### 9.2 决定正式采用后

不要直接把 Demo 整页复制到正式页面。先完成：

1. 明确正式四页面的信息架构和保留字段。
2. 增加同长度周期对比 API，避免进行中周期与完整周期误比。
3. 把动态文案加入 `src/shared/i18n.js` 的 `zh-CN` 和 `en`。
4. 复用 `src/shared/display.js` 的数字格式化能力。
5. 增加公开空数据、公开接口失败、Admin 401、Admin 空排名和大数据量测试。
6. 增加 E2E 覆盖周期切换、排行榜下钻、Admin 排名和页面刷新。
7. 给公开加载和 Admin 加载建立明确性能预算。
8. 完成浏览器视觉评审后，才允许 stage 和 commit。

### 9.3 决定放弃实验后

只恢复本 HANDOFF 列出的两个实验文件，不要重置整个工作区，也不要影响提交 `83e31a10` 及其他用户改动。

执行任何恢复或删除前必须再次确认当前 `git status --short`，并获得明确授权。
