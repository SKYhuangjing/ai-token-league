## 1. Product State

AI Token League is a local-first usage collector plus public leaderboard for AI coding token usage.

Core rules:

- Ranking is based on `totalTokens`, defined as `inputTokens + outputTokens + cacheReadTokens + cacheWriteTokens`; reasoning tokens remain diagnostic/cost fields.
- For `claude_code_local` and `codex_local`, `inputTokens` is normalized at collection time to `raw input - cacheReadTokens - cacheWriteTokens`.
- `cursor_dashboard_usage` keeps the Cursor dashboard API definition as-is; it is not locally redefined.
- Estimated cost is optional display, not the ranking truth.
- No prompt, assistant response, source code, full transcript, real absolute path, Cursor session token, or identity private key may be uploaded.
- Workdir display uses privacy-preserving hash plus public display name or alias.
- Cursor dashboard events do not expose real project paths; Cursor workdir remains virtual: `Cursor` or `Cursor · <account>`.

Supported sources:

| Provider | On/Off owner | Scan behavior |
| --- | --- | --- |
| `claude_code_local` | Sources card | scans local Claude Code project logs when On |
| `codex_local` | Sources card | scans local Codex session logs when On |
| `cursor_dashboard_usage` | Sources card | accesses Cursor dashboard usage API only when On |

Cursor token rules:

- `Add Cursor token` opens a modal, not a browser prompt.
- Supported input: `WorkosCursorSessionToken=...`, `user_xxx::accessToken`, pure JWT access token, or Cursor account JSON.
- Token format is validated locally before save.
- Valid tokens are stored locally, deduped, and shown only as account summaries.
- Saving a Cursor token enables the Cursor source.

## 2. Performance Baseline

Sources On/Off is a configuration action, not a usage refresh action.

Interaction rules:

- Clicking a source On/Off updates the card optimistically.
- The click path saves config and refreshes source health only.
- The click path must not call `loadToday(true)`.
- The click path must not force local usage scanning.
- The click path must not call Cursor dashboard usage APIs.
- Usage totals refresh only through Today Refresh, Trend Refresh, sync, or background refresh.
- Provider config changes still invalidate the usage cache so the next explicit refresh uses the correct provider set.

Reason:

- Local providers can scan many files.
- Cursor usage requires network calls and pagination.
- A small settings toggle must not inherit the latency and failure modes of usage collection.

Desktop pages:

| --- | --- |

| Trend | Daily 30d, Weekly 12w, Monthly 12m personal review |

Sources UI:

- No standalone `Cursor dashboard` settings block.
- No standalone `Enable Cursor usage` checkbox.
- No persistent Workos token input field.
- Cursor token entry is modal-only.
- Source cards show state, source count, description, roots/accounts, and an On/Off control.

## 4. Collector Baseline

Collector registry:

```text
claude_code_local
codex_local
cursor_dashboard_usage
```

Config fields:

```text
providerEnabled.claude_code_local
providerEnabled.codex_local
cursorDashboardUsage.enabled
cursorDashboardUsage.workosSessionTokens
providerRoots
workdirAliases
```

Provider semantics:

- `providerEnabled.<provider> = false` prevents local provider scanning but preserves configured roots.
- `cursorDashboardUsage.enabled = false` prevents Cursor dashboard scan sources from being returned.
- Provider health may still report detected roots/accounts while a source is Off.
- Cursor health can detect locally available token sources without scanning usage events.
- `claude_code_local` and `codex_local` emit normalized non-cache `inputTokens`; cache remains in `cacheReadTokens` and `cacheWriteTokens`.
