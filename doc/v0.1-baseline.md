# AI Token League v0.1 Baseline

Version: `0.1`
Frozen at: `2026-04-30`
Status: macOS local MVP verified; Windows x64 bundle generated, pending Windows host E2E.

This document is the stable baseline for the next development phase. The long product design and task tracking files remain the detailed historical record; new work should start from this baseline and then create new versioned tasks.

## 1. Product Baseline

AI Token League is a public community leaderboard for AI coding token usage.

Core product rules:

- No login and no real-name identity.
- A local anonymous identity owns `participantId + identityKey`.
- Identity can be exported and imported to another device.
- Public ranking is based on `totalTokens`.
- Estimated cost is a secondary display capability, not the default ranking metric.
- The service must never receive prompt, assistant response, source code, full transcript, real absolute path, Cursor session token, or identity private key.
- Workdir is maintained as privacy-preserving `workdirHash + displayName`; alias can override display name.
- If no alias exists, show the system-detected directory name.

Supported v0.1 sources:

| Provider | Status | Workdir behavior |
| --- | --- | --- |
| `codex_local` | supported | local workdir can be resolved from logs when available |
| `claude_code_local` | supported | local workdir can be resolved from logs when available |
| `cursor_dashboard_usage` | supported when explicitly enabled | fixed display name `Cursor`; Cursor dashboard API does not provide project/workdir |

Explicitly out of v0.1:

- Hook-based collection.
- Strong anti-cheat.
- Accounts, password login, OAuth, SSO.
- Team/private rooms.
- Cursor local workdir attribution.
- Windows host E2E verification.

Local storage:

| Logical data | v0.1 physical storage |
| --- | --- |
| identity, roots, aliases, provider config | `~/.ai-token-league/config.json` |
| usage cache | Electron `userData/usage-cache.json` |
| upload queue | `~/.ai-token-league/upload-queue.json` |
| backend MVP storage | `data/db.json` |

Preservation rule:

- Store the minimum daily fact granularity needed for future analysis.
- UI can show summaries, but upload and backend storage must preserve token fields by model, provider, workdir hash, day, participant, and device.
- Cost can be recalculated later from model prices; raw token facts must not be overwritten by price changes.

## 4. UI Baseline

Desktop:

| Page | Purpose |
| --- | --- |
| Today | local daily usage, model usage, workdir usage, last scan time |
| Trend | personal usage review: Daily 30d, Weekly 12w, Monthly 12m |
| Settings / Profile | nickname, export profile, import profile |
| Settings / Display | show estimated cost, raw token numbers |
| Settings / Sync | API base URL, background refresh, refresh interval |
| Settings / Sources | Codex roots, Claude Code roots, Cursor dashboard usage |
| Settings / Aliases | workdir public aliases |
| Settings / System | launch at login |

Web:

| Page | Purpose |
| --- | --- |
| `/` | public community leaderboard; ordinary user view |
| participant detail drawer | explain selected participant's ranking-period composition |
| `/admin.html` Usage ranking tab | operational query of usage aggregates |
| `/admin.html` Model prices tab | model price maintenance and missing price handling |

Chart rule:

- Compact charts must not become long scrolling tables.
- Hover/focus tooltip must show date/period, full token count, and cost when available.
- Token display defaults to compact units such as `1.20亿` and `8045万`; raw integers remain available in title, tooltip, raw mode, or details.
- Cost display is estimated. If some models are missing prices, show the known subtotal with `*`; if all models are missing prices, show `-`.

## 5. API Baseline

Current API surface:

```text
POST /api/devices/register
POST /api/usage/upload
GET  /api/leaderboard
GET  /api/participants/:participantId/detail
GET  /api/admin/usage
GET  /api/model-prices
POST /api/admin/model-prices
GET  /api/health
```

Query rules:

- Public leaderboard supports fixed ranking periods: today, yesterday, this week, last week, this month, last month.
- Admin usage ranking owns its own filters: quick ranges, custom date range, participant, auto/day/week/month grain, raw token toggle, estimated cost toggle.
- Model price management is separated from usage ranking filters.

## 7. v0.2 Preparation

Next version should not continue appending unrelated tasks to the v0.1 task log. Create a new version section or file before implementation.

Recommended v0.2 candidates:

- E18 test deployment with Docker Compose and MySQL.
- Windows host E2E and packaging polish.
- Persistent database migration hardening beyond the initial MySQL test store.
- Admin authentication or deployment boundary if exposed beyond local network.
- Better model price import/update workflow and pricing version history.
- Cursor provider hardening: pagination, token expiry handling, safer local token discovery.
- Export/import or backup of local usage cache.
- Public leaderboard moderation and basic abuse controls.
- Optional team/private board concept, only after public board behavior is validated.

Do not start v0.2 until the target outcome, success criteria, and migration boundary are written down.
