Cloud usage snapshot sync 新增验证点：

- legacy `/api/usage/daily-batch` payload 不带 `snapshot` 时仍保持 upsert-only，不删除缺失 rows。
- snapshot payload 的签名覆盖 `snapshot` 和 `items`；签名不匹配、bucket 混 day/hour/provider/device 时失败。
- snapshot-capable client 使用 protocol version 2 或等价 named threshold；`MIN_CLIENT_ENFORCE` 有明确阈值来源。
- 首次 protocol-v2 sync 在没有本地 manifest 时上传全部本地 `day + hour + providerId` buckets。
- manifest 独立文件原子写入；manifest 缺失、损坏或部分写入时等同 no manifest 并触发 full bucket resync。
- 后续 sync 只上传 fingerprint 变化的 dirty buckets。
- fingerprint 只使用 baseline 列出的稳定字段；不同客户端版本对同一 rows 计算一致。
- snapshot replace 只删除同 `participantId + deviceId + day + hour + providerId` bucket 内缺失的旧 rows。
- MySQL snapshot replace 在事务内完成；不复用 `syncAllTables()` 全量 flush；并发请求不会出现 upsert 成功但 delete/metadata 失败的半提交状态。
- MySQL 多实例部署下，两个独立 backend/store 实例连接同一数据库时，写入入口必须通过同一个 MySQL named lock 串行进入共享镜像写区；锁超时必须失败而不是无锁继续写。
- 同一天多 provider、同 participant 多 device 互不误删。
- provider disabled 或本地 bucket 完全缺失时不触发 empty-bucket deletion。
- offline queue replay 对同一 bucket fingerprint 幂等。
- offline queue drain 同时兼容旧 whole-history queue entry 和新 bucket snapshot entry，通过 `entry.payload.snapshot` 区分格式，旧 entry 不触发 delete。
- `scripts/query-usage-daily.js --env env.test` 可用于核对 `usage_daily` / `usage_hourly` raw rows、`workdirHash`、`sourceFingerprint`、`uploadedAt` 和 sync metadata。
